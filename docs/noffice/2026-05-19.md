- **[#4] Settings 탭 — Remote/Local 소스 모드 전환**
  - **개요**: NAtlas가 LLMWiki 문서를 조회하는 방식을 유연화할 필요가 있었다. 기존에는 로컬 클론만 지원했으나, 사내 Private 리포지터리에 GitHub API로 직접 접근하는 Remote 모드가 요구됐다.
  - **성과**: GitHub Token 기반 Remote 모드와 로컬 경로 기반 Local 모드를 전환할 수 있게 됐다. 리포 주소는 시스템 내부에 고정(NSoft-America-Inc/NSoft-LLMWiki)되어 사용자 설정 부담이 최소화됐다. CSP 정책 조정으로 Electron 환경에서의 API 통신 차단 문제도 해소됐다.
  - **참조**: [GitHub Issue #4](https://github.com/NSoft-America-Inc/NAtlas/issues/4)

- **[#5] Documents 탭 — 문서 분류 및 마크다운 뷰어**
  - **개요**: LLMWiki 문서가 늘어남에 따라 프로젝트·사용자·상태별 필터링과 문서 내용 미리보기 기능이 필요했다.
  - **성과**: 카테고리/프로젝트/유저/상태 필터 드랍다운이 추가됐고, 문서를 클릭하면 우측 패널에서 마크다운으로 렌더링된 내용을 바로 확인할 수 있게 됐다. 특히 이슈 단위 3종 문서(order/report/knowledge)가 컬러 뱃지와 slug명으로 구분 표시되어 가독성이 개선됐다.
  - **참조**: [GitHub Issue #5](https://github.com/NSoft-America-Inc/NAtlas/issues/5)

- **[거버넌스] LLMWiki 폴더 구조 재편 (LLMWiki#17)**
  - **개요**: SwarmVault 도입 이후 기존 PARA 구조가 실제 워크플로우와 맞지 않는 부분이 있었다. LLM 쿼리 파이프라인과 NAtlas 문서 탐색을 동시에 지원하는 구조가 필요했다.
  - **성과**: 작업 단위 3종 문서(order/report/knowledge)를 `content/01-Logs/archive/{project}/{user}/{slug}/` 경로에 통합하는 구조로 확정됐다. `swarmvault.schema.md`와 `PARA_Methodology.md`가 새 구조에 맞게 갱신됐고, 기존 `tasks/` 산하 knowledge 문서 4건이 해당 archive slug로 이전됐다.
