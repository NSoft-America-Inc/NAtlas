# 발표 의도 설계서 (Presentation Intent Document)

> 이 문서는 각 장표 MD를 점검·개선하는 기준 문서입니다.
> MD를 수정하기 전에 반드시 이 문서의 해당 슬라이드 의도를 확인합니다.

---

## 전체 발표 목표

**대상**: NSoft 전사 개발자 (AI/LLM 지식이 깊지 않은 사람 포함)
**목적**: NStack + NAtlas를 전사 도입시키기 위한 설득
**전략**: 문제 공감 → 해결책 제시 → 실제 동작 증명 → 즉시 시작 유도

### 청중이 발표 후 가져가야 할 것

1. "우리가 겪는 문제가 바로 이거였구나" (공감)
2. "NStack이 뭔지 동료에게 설명할 수 있다" (이해)
3. "NAtlas로 뭘 할 수 있는지 알겠다" (활용 이미지)
4. "오늘 퇴근 전에 Claude Code를 설치해봐야겠다" (행동)

### 금지 사항

- 코드 레벨 구현 설명 (Zustand, useMutation, IPC 채널 등)
- 청중이 모르는 고유명사를 설명 없이 사용
- "검증됐다" 주장만 있고 청중이 체감할 수 있는 예시가 없는 슬라이드

## 서사 구조 (Narrative Arc)

```
PART 1: "이 고통, 당신도 겪고 있죠?" (공감)
    ↓
PART 2: "NStack이 어떻게 해결하는지" (이해)
    ↓
PART 3: "직접 보여드리겠습니다 — 신규 개발" (증명)
    ↓
PART 4: "이어서 마이그레이션, 그리고 NAtlas 소개" (증명 + 전환)
    ↓
PART 5: "NAtlas로 이런 것들을 할 수 있습니다" (활용 이미지)
    ↓
PART 6: "오늘부터 시작하세요" (행동 유도)
```

## PART 2 — NStack이 무엇인가 (11장)

**파트 목표**: 청중이 NStack의 3단계 흐름(계획 → 실행 → 보존)을 머릿속에 그릴 수 있어야 한다.
Part 2 후반(slide07~11)은 자동 검사기 설명인데, 이게 "왜 좋은가"를 먼저 말하지 않으면 지루해진다.
