# order.md 실물 — 이렇게 생겼습니다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 실제 order.md 문서를 에디터 화면처럼 보여주는 **Document Walkthrough Layout**. 좌측에 실물 문서 구조, 우측에 각 섹션 설명.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 (에디터 뷰, 다크 배경)**: 실제 order.md의 4개 섹션이 코드 에디터처럼 표시됨. 각 섹션마다 다른 색상으로 하이라이트.
    - `## 1. 왜 이 작업을 합니까` (파랑)
    - `## 2. 무엇을 어떻게 만듭니까` (퍼플)
    - `## 3. 어떤 파일을 건드립니까` (에메랄드)
    - `## 4. 어디까지 하면 완료입니까` (앰버)
  - **우측 설명 패널**: 각 섹션이 왜 있는지 한 줄 설명.
  - **하단 배지**: "작성 시간: 5분 / AI가 이 문서를 보고 작업합니다"

## 2. 실질적 본문 내용 (Exact Slide Content)

### order.md는 4개 섹션으로 구성됩니다

AI에게 작업을 시키기 전에, 이 4가지만 정리하면 됩니다:

**1. 왜 이 작업을 합니까 (배경과 목적)**
- 이 기능이 왜 필요한지, 무엇을 해결하는지를 씁니다
- AI가 방향을 잡는 데 가장 중요한 섹션입니다

**2. 무엇을 어떻게 만듭니까 (구현 내용)**
- 어떤 기능을 만들 것인지, 어떤 방식으로 만들 것인지를 씁니다
- 구체적일수록 AI가 더 정확하게 작동합니다

**3. 어떤 파일을 건드립니까 (작업 범위)**
- 이번 작업에서 수정할 파일 목록을 씁니다
- 이 목록 밖의 파일은 건드리지 않습니다

**4. 어디까지 하면 완료입니까 (완료 기준)**
- "이게 되면 끝"을 체크리스트로 정의합니다
- AI와 개발자 모두 이 기준으로 완료를 판단합니다

이 4가지가 있으면 AI는 지시서의 범위 안에서만 작동합니다. 그리고 이 문서가 GitHub 이슈와 연결되어 나중에 역추적이 됩니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"order.md가 실제로 어떻게 생겼는지 보여드리겠습니다. 4개 섹션이 전부입니다. 왜 이 작업을 하는지, 무엇을 어떻게 만드는지, 어떤 파일을 건드리는지, 어디까지 하면 완료인지. 이 4가지를 정리하는 데 약 5분이면 됩니다. 이 문서를 AI에게 주면 AI는 이 범위 안에서만 작동합니다. 범위 밖의 파일은 건드리지 않습니다. 그리고 이 문서는 GitHub 이슈와 1:1로 연결되어, 나중에 이 코드가 왜 만들어졌는지 역추적할 수 있습니다."*
