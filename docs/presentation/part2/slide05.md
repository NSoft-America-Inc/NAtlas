# Slide 14: 문서를 검색 가능하게 만드는 공통 태그 체계

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 마크다운 최상단의 비정형 데이터를 원자 단위 필드로 고속 해독하여 전사 지식 지도 데이터베이스로 사상하는 **YAML 메타데이터 파서 레이아웃 (YAML Metadata Parser)**.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 비주얼**: 마크다운 최상단의 raw YAML 블록이 파란색 여과장치(Filter Pipe)를 수직 통과하면서 분기되어, 정밀 가공된 데이터 필드(`title`, `issue_url`)로 칼같이 쪼개어 정렬 저장되는 데이터 매퍼 SVG.
  - 파이프 엣지에 은은한 푸른색 LED 네온 글로우가 점멸하고, 파싱된 텍스트 조각들이 실시간 비동기 흐름으로 사상되는 구조도 렌더링.

## 2. 실질적 본문 내용 (Exact Slide Content)

### 🔑 NAtlas 고속 지식 네트워크를 형성하는 메타데이터 원자화 규정

단순한 마크다운 파일들의 집합은 검색과 인덱싱의 관점에서 커다란 노이즈 덩어리일 뿐입니다. NAtlas가 저장소의 모든 지식 아카이브 문서를 로딩 시간 **0.05초 만에 초고속으로 해독**하고 3D 물리 지식 네트워크 그래프를 그리기 위해서는, 모든 문서의 가장 첫머리에 완벽히 규격화된 **YAML Frontmatter 규격**이 탑재되어 지식의 원자성을 보장해야 합니다.

- **📜 필수 사양 YAML 블록 구조 [Standard Specification]**:
  - 모든 문서 최상단에 `---` 구분자로 둘러싸인 메타데이터 영역을 강제화합니다.
  - **`title`**: 작업에 대한 구체적이고 한눈에 이해되는 국문 명칭 기재 의무.
  - **`issue_url`**: 해당 작업이 위임되고 추적되는 GitHub 이슈 공식 주소 바인딩.
- **⚡ 실시간 파싱 및 네트워크 빌드 [Instant Parsing & Mapping]**:
  - NAtlas GUI 브라우저는 문서를 여는 순간 전체 본문을 헤맬 필요 없이, Frontmatter의 YAML 블록만 고속 컴파일하여 SQLite 메타 테이블에 캐싱합니다.
  - 이 메타데이터는 다른 문서의 `[[이중 대괄호]]` 인용 관계와 합쳐져, 전사 지식 3D 노드 간의 자성 인력 및 척력 가동을 위한 물리 에너지 값으로 승화됩니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"대충 적은 마크다운 문서는 지식 자산이 아닌 '쓰레기 덩어리'일 뿐입니다. 기계와 인간이 동시에, 그리고 순식간에 정보를 매핑하려면 Frontmatter라는 '원자적 인덱싱'이 필수적입니다. NStack을 적용한 저장소의 모든 마크다운 파일은 최상단에 `title`과 `issue_url`을 규정하는 표준 YAMLFrontmatter를 반드시 기재해야 합니다. NAtlas 브라우저는 이 YAML 블록만 0.01초 만에 파싱하여 지식 노드를 그리고 관계선을 뿜어냅니다. Frontmatter의 표준화가 지식 데이터베이스의 고속 렌더링과 만유인력 그래프를 이루는 가장 밑바탕의 튼튼한 주춧돌이 됩니다."*
