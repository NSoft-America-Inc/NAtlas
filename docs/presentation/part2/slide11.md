# 제목을 조금 다르게 써도 괜찮습니다 — 유연하게 인식합니다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 다양한 표현이 하나로 매핑되는 것을 보여주는 **Flexible Mapping Layout**. 좌측에 다양한 표현들, 중앙에 매핑 화살표, 우측에 공식 섹션명.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 (다양한 표현, 파랑 계열)**:
    - `## 수정된 파일 목록`
    - `## 🛠️ 변경사항`
    - `## 바뀐 파일들`
    - `## Changes (변경)`
  - **중앙 화살표**: `→ 인식됨 ✅`
  - **우측 (공식 섹션, 에메랄드)**: `## 변경된 파일 (Changes)`
  - **하단**: "정해진 형식을 외울 필요 없습니다. 의미가 통하면 인식됩니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### 검사기가 너무 엄격하면 — 쓰기 싫어집니다

문서 자동 검사기를 도입할 때 가장 큰 불만: **"정확한 제목을 외워야 해서 귀찮다"**

이걸 해결하기 위해 NStack 자동 검사기는 유연하게 작동합니다:

- `수정된 파일 목록`이라고 써도 인식됩니다
- `🛠️ 변경사항`이라고 이모지를 붙여도 됩니다
- `바뀐 파일들`처럼 자유롭게 써도 됩니다
- 한글과 영어를 섞어 써도 됩니다

**어떻게 가능한가**: 검사기가 제목에서 핵심 의미를 파악합니다. "변경", "수정", "바뀐", "changes" — 이 단어들이 있으면 같은 섹션으로 인식합니다.

**단, 내용은 엄격합니다**: 제목은 유연하게 받아주지만, 그 안에 실제 내용이 있어야 합니다.

이 유연함 덕분에 팀원들이 규칙을 외우는 데 시간 쓰지 않고, 자연스럽게 쓸 수 있습니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"자동 검사기가 너무 엄격하면 어떻게 될까요? '정확한 섹션 제목을 외워야 해서 귀찮다'는 불만이 생기고, 결국 문서 자체를 기피하게 됩니다. NStack은 이걸 유연하게 만들었습니다. '수정된 파일 목록'이라고 써도, '🛠️ 변경사항'이라고 써도, '바뀐 파일들'이라고 써도 같은 섹션으로 인식합니다. 검사기가 제목에서 의미를 파악하기 때문입니다. 대신 내용 검사는 엄격합니다. 제목은 자유롭게 쓰되, 안에 실제 내용이 있어야 합니다. 팀원이 규칙 외우는 데 에너지를 쓰지 않아도 되도록 설계했습니다."*
