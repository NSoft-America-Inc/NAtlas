# 3가지 문서 — 각각 어떤 역할을 하는가

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 3개의 문서 카드를 세로로 배치하는 **Vertical Card List Layout**. 각 카드는 이름, 역할, 담는 내용, 쓰는 시점을 한눈에 보여줌.
- **비주얼 및 컴포넌트 구성**:
  - **카드 1 (파랑, order.md)**: 📋 작업 지시서. "작업을 시작하기 전에 씁니다." 아이콘과 함께 "목적 / 작업 범위 / 완료 기준" 3개 키워드 배지.
  - **카드 2 (에메랄드, wiki.md)**: 🧠 지식 보존서. "작업이 끝나면 씁니다." "왜 이렇게 만들었는가 / 어떤 고민이 있었는가 / 주의사항" 3개 키워드 배지.
  - **카드 3 (퍼플, report.md)**: 📊 진행 보고서. "작업 중에 씁니다." "무엇을 했는가 / 무엇이 남았는가 / 어떤 결과가 나왔는가" 3개 키워드 배지.
  - **하단 강조**: "이 3가지가 쌓이면 — AI도, 사람도 언제든 맥락을 이어받을 수 있습니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### NStack의 3가지 문서 — 언제, 무엇을, 왜 씁니까

NStack은 3가지 문서를 씁니다. 각각 언제 쓰고 무엇을 담는지가 명확하게 정해져 있습니다.

**① order.md — 작업 지시서** (작업 전에 씁니다)
- **담는 내용**: 오늘 무엇을 만드는가, 왜 만드는가, 어디까지 하면 완료인가
- **역할**: AI가 이 문서를 보고 작업합니다. 범위가 명확하니 엉뚱한 곳을 건드리지 않습니다.
- **쓰는 시간**: 5분

**② wiki.md — 지식 보존서** (작업 후에 씁니다)
- **담는 내용**: 왜 이 구조를 선택했는가, 어떤 대안이 있었는가, 주의해야 할 것은 무엇인가
- **역할**: 미래의 나, AI, 팀원이 이 문서를 보면 처음부터 읽지 않아도 됩니다.
- **쓰는 시간**: AI가 초안을 씁니다

**③ report.md — 진행 보고서** (작업 중에 씁니다)
- **담는 내용**: 오늘 무엇을 했는가, 무엇이 남았는가, 어떤 결과가 나왔는가
- **역할**: 작업 상황을 투명하게 공유하고, 다음 작업이 어디서 이어받는지 알 수 있습니다.
- **쓰는 시간**: AI가 초안을 씁니다

## 3. 스피치 노트 (Aside Speaker Notes)

*"NStack의 3가지 문서가 각각 어떤 역할을 하는지 설명드리겠습니다. order.md는 작업 전에 쓰는 지시서입니다. 오늘 무엇을 왜 만드는지 5분 안에 정리합니다. wiki.md는 작업이 끝나고 쓰는 지식 보존서입니다. 왜 이런 구조를 선택했는지를 남깁니다. AI가 초안을 써줘서 개발자가 직접 긴 글을 쓸 필요는 없습니다. report.md는 작업 중에 쌓이는 진행 보고서입니다. 오늘 뭘 했고 뭐가 남았는지를 기록합니다. 이 3가지가 쌓이면, 다음 번 AI에게 이 문서를 주면 맥락을 바로 이어받습니다."*
