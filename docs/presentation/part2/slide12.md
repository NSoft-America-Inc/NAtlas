# 오류가 발견되면 어떻게 고치면 되는지도 알려줍니다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 오류 메시지와 해결 방법을 나란히 보여주는 **Error + Fix Layout**. 좌측에 오류 화면, 우측에 수정 후 결과.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 (오류 상황, 터미널 스타일)**:

    ```
    ❌ 오류 발견: order.md

    문제 1: "왜 이 작업을 합니까" 섹션이 없습니다
    문제 2: "완료 기준" 내용이 너무 짧습니다 (3자)

    → 자동 수정하려면: nstack --fix
    ```

  - **우측 (수정 후, 에메랄드 테두리)**:

    ```
    ✅ 수정 완료

    - "왜 이 작업을 합니까" 섹션 추가됨
    - "완료 기준" 작성 안내 추가됨

    → 내용을 채운 후 다시 커밋하세요
    ```

  - **하단**: "무엇이 문제인지, 어떻게 고치면 되는지 — 둘 다 알려줍니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### 빨간 에러 메시지만 보여주면 — 개발자는 화가 납니다

대부분의 자동 검사기는 이렇게만 합니다:

- "❌ 오류 발생" — 끝

개발자는 "그래서 뭘 어떻게 해야 하지?"를 혼자 파악해야 합니다.

NStack 자동 검사기는 다릅니다. 오류가 발견되면:

**1. 무엇이 문제인지 정확하게 알려줍니다**

- "왜 이 작업을 합니까 섹션이 없습니다"
- "완료 기준 내용이 너무 짧습니다"

**2. 자동으로 고쳐주는 옵션도 있습니다**

- `nstack --fix` 명령어 하나로 문서 형식을 자동 수정합니다
- 없는 섹션은 추가됩니다
- 개발자는 내용만 채우면 됩니다

**3. 다시 커밋하면 됩니다**

- 수정 후 커밋 → 자동 검사 → 통과 → 저장됩니다

**결과**: 오류가 나도 막막하지 않습니다. 무엇을 고쳐야 하는지 바로 알고, 고치는 것도 쉽습니다.

## 3. 스피치 노트 (Aside Speaker Notes)

_"오류가 나면 대부분의 검사기는 '틀렸다'고만 합니다. 뭘 어떻게 고쳐야 하는지는 개발자가 알아서 파악해야 하죠. NStack은 '무엇이 문제이고 어떻게 고치면 되는지'를 같이 알려줍니다. 섹션이 없으면 없다고 알려주고, 내용이 짧으면 짧다고 알려줍니다. 자동 수정 기능도 있습니다. 명령어 하나로 문서 형식이 자동으로 만들어집니다. 개발자는 빈 칸에 내용만 채우면 됩니다. 오류가 나도 막막하지 않게 — 이게 NStack 자동 검사기가 지향하는 방향입니다."_
