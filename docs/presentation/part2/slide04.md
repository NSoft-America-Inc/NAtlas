# Slide 15-A: 실제로 어떻게 쓰나 — 개발자 하루 루틴

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 개발자의 하루 작업 흐름을 시간대별로 보여주는 **Daily Timeline Flow Layout**. 세로 타임라인 축을 따라 아침→낮→저녁 3구간이 펼쳐지고, 각 시점에서 개발자와 AI가 무엇을 하는지 대화 버블 형식으로 표시됩니다.
- **비주얼 및 컴포넌트 구성**:
  - **왼쪽 컬럼 (개발자)**: 사람 아이콘과 함께 각 단계에서 개발자가 하는 일.
  - **오른쪽 컬럼 (AI 에이전트)**: 로봇 아이콘과 함께 AI가 하는 일.
  - **하단 결과 배너**: "오늘 작업이 끝나면, 지식이 자동으로 팀 저장소에 쌓인다." 에메랄드색 강조 배너.

## 2. 실질적 본문 내용 (Exact Slide Content)

### 🗓️ NStack을 쓰는 개발자의 하루 — 생각보다 훨씬 단순하다

NStack을 처음 보면 "또 문서를 써야 하나?"라는 생각이 들 수 있습니다. 실제로는 다릅니다. **개발자가 직접 써야 하는 것은 딱 하나**, 처음에 작업 지시서를 정리하는 것뿐입니다.

- **🌅 시작 (5분) — order.md 작성**:
  - "오늘 뭘 만들지"를 order.md 양식에 간단히 정리합니다.
  - 목적, 작업 범위, 완료 기준만 쓰면 됩니다. 팀장이나 Claude가 검토하면 시작.
- **☀️ 낮 — AI 에이전트가 구현, 개발자는 검토**:
  - AI가 order.md를 보고 실제 코드를 작성합니다.
  - 개발자는 방향이 맞는지 확인하고, 필요하면 조정합니다.
  - 코드가 완성되면 자동 검사기가 문서 품질을 체크합니다.
- **🌆 마무리 — report.md + wiki.md 기록**:
  - 오늘 작업 결과를 report.md에 정리합니다 (AI가 초안 작성).
  - 이 프로젝트에서 배운 것, 결정한 것을 wiki.md로 남깁니다.
  - **커밋하면 끝.** 자동 검사기가 이 문서들이 제대로 됐는지 확인해줍니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"실제로 NStack을 쓰는 개발자가 추가로 해야 할 일은 무엇일까요? 생각보다 간단합니다. 하루 시작에 5분 정도 order.md를 정리하는 것이 전부입니다. 그 다음은 AI 에이전트가 가이드를 보고 알아서 구현하고, 개발자는 그게 맞는 방향인지 검토합니다. 끝나면 결과 보고서와 위키 문서를 남기는데, 이것도 AI가 초안을 써주기 때문에 개발자가 직접 긴 글을 쓸 필요가 없습니다. 커밋을 올리면 자동 검사기가 '문서가 제대로 됐나' 확인해주고, 통과하면 완료입니다. 이 흐름이 반복되면 팀 전체의 지식이 자연스럽게 쌓입니다. 처음 몇 번만 익숙해지면, 이게 오히려 AI에게 맥락 없이 계속 설명해야 하는 것보다 훨씬 편합니다."*
