# 실제로 어떻게 쓰나 — 개발자 하루 루틴

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 개발자의 하루 작업 흐름을 시간대별로 보여주는 **Daily Timeline Flow Layout**. 세로 타임라인 축을 따라 시작→작업 중→마무리 3구간이 펼쳐지고, 각 시점에서 개발자와 AI가 무엇을 하는지 표시됩니다.
- **비주얼 및 컴포넌트 구성**:
  - **왼쪽 컬럼 (파랑, 개발자)**: 각 단계에서 개발자가 하는 일 (짧고 구체적으로).
  - **오른쪽 컬럼 (에메랄드, AI)**: 각 단계에서 AI가 하는 일.
  - **타임라인 배지**: "시작 5분", "AI가 진행", "마무리 5분".
  - **하단 결과 배너 (에메랄드)**: "오늘 작업이 끝나면, 지식이 자동으로 팀 저장소에 쌓입니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### NStack을 쓰는 개발자의 하루 — 생각보다 훨씬 단순합니다

처음 보면 "또 문서를 써야 하나?"라는 생각이 들 수 있습니다. 실제로는 다릅니다.

**시작 (5분) — order.md 작성**

- 개발자: "오늘 이 기능을 이 이유로 만든다"를 간단히 정리합니다
- AI: 지시서를 확인하고 작업 계획을 세웁니다

**작업 중 — AI가 구현, 개발자는 검토**

- AI: order.md를 보고 코드를 작성합니다
- 개발자: 방향이 맞는지 확인하고, 필요하면 조정합니다
- 자동으로: 문서 품질을 체크합니다 (사람이 직접 확인 안 해도 됩니다)

**마무리 (5분) — 기록 완료**

- AI: 오늘 작업 결과와 이유를 report.md, wiki.md로 정리합니다
- 개발자: 확인하고 커밋하면 끝입니다

---

**개발자가 직접 쓰는 것**: 하루 시작 5분, 작업 지시서 하나.
나머지는 AI가 합니다. 개발자는 방향을 잡고 결과를 확인합니다.

## 3. 스피치 노트 (Aside Speaker Notes)

_"실제로 NStack을 쓰는 개발자가 추가로 해야 할 일은 무엇일까요? 생각보다 간단합니다. 하루 시작에 5분 정도 order.md를 정리하는 것이 전부입니다. 나머지는 AI가 알아서 합니다. 코드도 구현하고, 문서 초안도 씁니다. 개발자는 방향이 맞는지 확인하고, 마무리에 커밋하면 됩니다. 이 흐름이 반복되면 팀 전체의 지식이 자연스럽게 쌓입니다. 처음 몇 번만 익숙해지면, AI에게 매번 처음부터 설명하는 것보다 훨씬 편합니다."_
