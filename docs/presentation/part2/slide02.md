# NStack을 쓰면 개발자도 좋고, AI도 좋습니다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 사람과 AI 양쪽의 혜택을 대칭으로 보여주는 **Dual Benefit Split Layout**. 좌측은 사람, 우측은 AI. 중앙에 NStack 로고와 연결 화살표.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 패널 (파랑, 사람)**: 개발자 아이콘. "다음에 봐도 이해된다", "인수인계가 쉬워진다", "온보딩이 빨라진다" 3가지 배지.
  - **우측 패널 (에메랄드, AI)**: AI 아이콘. "매번 처음부터 설명 안 해도 된다", "핵심만 전달된다", "더 빠르고 정확하게 작동한다" 3가지 배지.
  - **중앙 화살표**: 양방향 순환. "문서가 쌓일수록 선순환"
  - **하단**: "지식이 남을수록 AI도 더 잘 되고, 사람도 더 편해집니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### 한쪽만 편한 게 아닙니다 — 사람도, AI도 동시에 좋아집니다

NStack의 핵심 원리는 간단합니다: **"왜 이렇게 만들었는지"를 매번 기록하면, 사람과 AI 모두 다음 번이 더 쉬워집니다.**

**사람에게 생기는 변화**:
- 6개월 전 코드를 다시 봤을 때 — 문서에 이유가 있어서 바로 이해됩니다
- 팀원이 새로 왔을 때 — 코드 전체를 처음부터 읽지 않아도 됩니다
- 인수인계할 때 — 레포지토리 주소 하나가 아니라 맥락까지 함께 전달됩니다

**AI에게 생기는 변화**:
- 새 대화창을 열어도 — 문서를 주면 AI가 맥락을 바로 이어받습니다
- 코드 38개 파일 대신 — 문서 3개만 주면 됩니다 (앞서 보신 95% 절감)
- AI가 더 정확하게 작동합니다 — 핵심만 전달받아서 집중할 수 있기 때문입니다

이 두 가지가 선순환입니다. 문서가 쌓일수록 AI가 더 잘 되고, AI가 잘 될수록 개발이 빨라지고, 그 결과가 다시 문서로 쌓입니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"NStack이 좋은 이유는 한 방향이 아닙니다. 사람과 AI 모두에게 동시에 좋아집니다. 사람 입장에서는 6개월 전 코드를 봐도 왜 이렇게 만들었는지 문서에 있어서 바로 이해됩니다. 팀원이 새로 와도 며칠 안에 자리잡을 수 있습니다. AI 입장에서는 매번 처음부터 설명 안 해도 됩니다. 문서를 주면 맥락을 이어받아서 훨씬 빠르고 정확하게 작동합니다. 이 두 가지가 선순환을 만들어냅니다. 지식이 쌓일수록 모든 것이 더 쉬워집니다."*
