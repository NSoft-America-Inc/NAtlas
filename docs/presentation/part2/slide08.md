# 커밋할 때 자동으로 문서를 검사합니다 — 사람이 일일이 확인 안 해도 됩니다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 자동 검사가 작동하는 흐름을 보여주는 **Auto-Check Flow Layout**. 좌측에 "커밋 시도" → 중앙에 "자동 검사" → 우측에 "통과/차단" 결과.
- **비주얼 및 컴포넌트 구성**:
  - **흐름 다이어그램**: `git commit` → `자동 검사기 실행` → 두 갈래 분기: `✅ 통과 → 저장소에 저장됨` / `❌ 차단 → 무엇이 문제인지 표시`
  - **중앙 검사기 아이콘**: 방패 모양 + 에메랄드 체크. "1초 안에 자동 실행"
  - **하단 강조**: "팀장이 매번 문서를 검수하지 않아도 됩니다. 시스템이 합니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### 문서 품질을 사람이 매번 확인하면 — 결국 아무도 확인하지 않게 됩니다

팀에 "문서를 꼭 써주세요"라고 아무리 강조해도, 바쁠 때는 형식만 채우거나 아예 빈 채로 올라오게 됩니다. 이것은 의지의 문제가 아닙니다. 확인하는 사람이 없으면 기준이 지켜지지 않습니다.

NStack은 이것을 자동화로 해결합니다:

- **코드를 저장소에 올릴 때마다 자동으로 검사가 실행됩니다**
  - 사람이 따로 확인하지 않아도 됩니다
  - 팀장이 문서를 일일이 리뷰하지 않아도 됩니다

- **문제가 있으면 저장 자체가 차단됩니다**
  - 빈 문서, 내용 없는 문서, 형식이 맞지 않는 문서는 통과하지 못합니다
  - 이유도 함께 표시됩니다 — "어디가 문제인지" 바로 알 수 있습니다

- **문제가 없으면 그냥 통과됩니다**
  - 잘 쓴 문서는 아무 방해 없이 저장됩니다
  - 불필요한 승인 과정이 없습니다

**결과**: 팀 전체가 "문서를 써야 할 이유"를 느낄 필요 없이, 구조가 알아서 기준을 지킵니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"아무리 '문서를 써주세요'라고 강조해도 바쁜 시기에는 지켜지지 않습니다. NStack은 이걸 자동화로 해결합니다. 코드를 저장소에 올릴 때마다 자동으로 문서를 검사합니다. 사람이 따로 확인할 필요가 없습니다. 문서가 문제가 있으면 저장 자체가 차단됩니다. 어디가 왜 문제인지도 바로 표시됩니다. 잘 쓴 문서는 그냥 통과됩니다. 팀원 모두가 의지를 갖지 않아도, 구조가 알아서 기준을 지키게 만드는 것 — 이것이 NStack 자동 검사기의 핵심입니다."*
