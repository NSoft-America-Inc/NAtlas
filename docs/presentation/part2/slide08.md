# Slide 17: 빈 껍데기 문서는 자동으로 차단된다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 템플릿의 내용 없는 무단 복제 및 방치 행위를 정밀 추적해 내는 **플레이스홀더 차단 매트릭스 레이아웃 (Placeholder Alert Matrix)**. 
- **비주얼 및 컴포넌트 구성**:
  - **좌측 비주얼**: 마크다운 본문 코드 뷰어 그래픽 위로, 수정되지 않고 방치된 레거시 템플릿 가이드 텍스트(예: `[여기에 작업의 배경]`, `TODO`)에 빨간색 레이저 돋보기 타겟 스캔 빔(`filter="url(#glow)"`)이 비추어지며 요란하게 점멸하는 경보 SVG 탑재.
  - 경보 부위에 `PLACEHOLDER DETECTED (BLOCK)`이라는 붉은색 경고 마커와 사이렌 그래픽 가미.

## 2. 실질적 본문 내용 (Exact Slide Content)

### 🚫 껍데기만 복사해 지식을 속이는 행위의 기계적 차단

개발 현장에서 템플릿을 도입할 때 가장 흔히 겪는 함정은, 개발자들이 양식을 복사만 해 두고 실제 내용은 채워 넣지 않은 채 빈 껍데기 문서만 푸시하는 것입니다. NStack 정적 린터는 이를 **'지식 오염 사기 행위'**로 간주하여, 단 한 줄의 가이드성 안내 문구라도 본문에 잔존해 있을 경우 가차 없이 빌드를 폭파시킵니다.

- **🚨 20여 종의 핵심 플레이스홀더 감지 [Blacklisted Placeholders]**:
  - 린터 엔진 내부의 `PLACEHOLDERS` 전역 배열에 `여기에 작업의 배경`, `여기에 구현할 내용`, `[Order]`, `[작업 배경 및 목표]`, `TODO` 등 방치되기 쉬운 20가지 이상의 템플릿 가이드용 특정 구절을 박제하여 감시합니다.
- **🔍 무관용 정규식 스캔 기동 [Zero-Tolerance RegEx Scan]**:
  - 마크다운 파싱 시점뿐만 아니라, 원문 텍스트 전체를 정규식 스트링 대조 방식으로 한 글자씩 스캔하여 단 하나의 매칭 단어라도 잔존할 시 즉각 위반 에러(`Placeholder Detected Exception`)를 던집니다.
  - 이를 통해 전사 저장소의 아티팩트 품질을 최소한의 타협도 없이 100% 무결하게 유지합니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"가장 흔한 문서화 실패 사례는 무엇일까요? 바로 개발자들이 귀찮아서 템플릿 껍데기만 복사해 올리고 정작 본문 알맹이는 빈 칸으로 두는 것입니다. NStack 린터는 이를 기계적으로 완벽히 격리합니다. 린터 내부에 약 20여 종의 '블랙리스트 가이드 단어' 배열을 장착해 두었습니다. '여기에 작성', '여기에 작업의 배경' 같은 템플릿에 들어있던 안내성 글귀가 본문에 단 한 글자라도 남아있거나, 'TODO'가 수정되지 않은 채 방치되어 있다면 방화벽이 번개처럼 타겟 빔을 쏴서 잡아냅니다. 어떠한 꼼수나 타협도 없이 순수한 알맹이 지식만 남도록 하는 극단의 품질 통제 조치입니다."*
