# 내용이 충분해야만 통과합니다 — 한 줄짜리 답변은 막힙니다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 통과되는 예시와 차단되는 예시를 나란히 보여주는 **Pass/Fail Comparison Layout**.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 (차단 예시, 붉은 테두리)**:
    ```
    ## 왜 이 작업을 합니까
    성능 개선
    ```
    → ❌ 차단: "내용이 너무 짧습니다"
  - **우측 (통과 예시, 에메랄드 테두리)**:
    ```
    ## 왜 이 작업을 합니까
    결제 페이지 로딩이 3초 이상 걸려 
    사용자 이탈률이 높아지고 있습니다.
    캐싱 레이어를 추가해 1초 이내로 
    줄이는 것이 목표입니다.
    ```
    → ✅ 통과
  - **하단**: "짧아도 형식은 맞습니다. 하지만 내용이 없는 짧은 답변은 지식이 아닙니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### 안내 문구를 지우고 "성능 개선" 두 글자만 써도 — 통과하면 안 됩니다

플레이스홀더를 지우고 아주 짧은 내용만 써서 통과하려는 시도가 있을 수 있습니다:

- `왜 이 작업을 합니까` → `성능 개선`
- `완료 기준` → `테스트 통과`

형식은 맞습니다. 하지만 이런 문서는 지식이 없습니다. 나중에 이 문서를 봤을 때 아무것도 알 수 없습니다.

NStack 자동 검사기는 **내용의 양도 기준으로 판단**합니다:

- 섹션 하나당 최소한의 글자 수가 있어야 합니다
- 공백, 줄바꿈, 안내 문구를 제외한 실제 텍스트를 기준으로 합니다
- 기준에 미달하면 → 차단됩니다. "내용이 너무 짧습니다"와 함께.

**목적**: 나중에 AI가, 팀원이, 미래의 내가 봤을 때 **실제로 이해할 수 있는 내용**이 있어야 합니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"빈 안내 문구를 지우고 대신 '성능 개선' 두 글자만 써도 차단될까요? 네, 차단됩니다. 형식은 맞지만 내용이 없기 때문입니다. 자동 검사기는 섹션별로 실제 텍스트의 양을 측정합니다. 너무 짧으면 차단됩니다. 이 기준이 있는 이유는 단순합니다. 나중에 이 문서를 봤을 때, AI가 봤을 때, 팀원이 봤을 때 실제로 이해할 수 있는 내용이 있어야 하기 때문입니다. '성능 개선'이라고만 써두면 6개월 뒤에 아무 의미가 없습니다."*
