기존 AI 협업의 한계와 새로운 돌파구

🚨 대화형 AI 코딩의 치명적인 한계 고발

기존의 단순 대화형 페어 프로그래밍은 장기 세션 진행 시 두 가지 결정적 리스크를 초래합니다.

  • 1. 비효율적인 토큰 소모 (Token Waste):
    사소한 리팩토링이나 수정을 수행할 때도 매번 수천 라인의 대용량 전체 코드를 프롬프트에 반복 주입해야 하여 인프라 비용 폭증.
  • 2. 장기 메모리 소실 및 컨텍스트 희석:
    대화 세션이 길어지면 과거에 합의한 아키텍처 결정사항이나 설계 의도를 LLM이 망각하여, 시스템의 기존 규칙을 어기는 엉뚱한 코드를 생산하기 시작.
  • NStack의 해결책: '외장 메모리 하드디스크':
    에이전트의 컨텍스트 창을 매번 청소하는 대신, 초경량화되고 응축된 3종 지식 캡슐(order/report/wiki)을 통해 핵심 컨텍스트와 설계 의도를 영구 보존.

지식 보존을 위한 3종 아티팩트의 구조 설계

📦 컨텍스트 희석을 원천 차단하는 3종의 무기

NStack은 개발의 단계별 아티팩트를 파일로 영구 보존하여 장기 세션에서의 컨텍스트를 완벽히 통제합니다.

  • order.md (작업지시서):
    작업 범위, 구현 환경의 사전 설정, 비즈니스 및 기술적 목표(Goal), 통제를 위한 완료 조건 명시
  • report.md (완료보고서):
    완료된 실제 세부 작업, 변경/추가 파일 목록, 정적 린터 및 분석 통과 검증 기록 보존
  • wiki.md (지식 위키 문서):
    최초 계획과 구현의 실제 격차, 선택 대안의 구체적 의사결정 사유, 유지보수 제약사항의 누적 보존

아티팩트 1: order.md (작업지시서)

작업을 시작하기 전에 기획 목표와 기술적 완성 기준을 확정해 에이전트의 작업 바운더리를 강력하게 제한합니다.

  • ## Git Setup:
    Git 브랜치와 PR 매핑 등 작업 수행 전 형상 관리 환경 사전 진단
  • ## Context & Goal:
    단순 문장을 넘어 비즈니스 배경과 기획 의도 등 풍부한 맥락의 사전 공유
  • ## Completion Criteria:
    기능 동작 완료뿐만 아니라 정적 린터 패스 조건까지 수치화된 정량적 인수 목록 기재

아티팩트 2: report.md (완료보고서)

🔬 변경 내역의 투명성과 작동 무결성 입증

작업이 완료된 후 실제로 변경된 모든 파일 목록과 정적 분석 검사 로그를 기재해 완벽한 작동을 입증합니다.

  • ## Completed Tasks:
    최초 계획의 완료 기준(Completion Criteria)과 100% 매핑된 완료 체크리스트 기재
  • ## Changes [NEW / MODIFY / DELETE]:
    워크스페이스 내부에서 수정되거나 생성/삭제된 구체적 파일의 기계적 파싱 태그 표기
  • ## Static Analysis (검증 로그):
    ESLint 및 정적 Linter를 실행한 무결점 입증 로그를 첨부하여 코드 결함을 선제 예방

아티팩트 3: wiki.md (지식 위키 문서)

🏛️ 설계의 비하인드 스토리와 결정 사유(Why) 영구 각인

구현 코드 그 자체보다 중대한 설계상 결정 사유와 우회 해결 전략, 유지보수 제약사항을 영구 보존합니다.

  • ## Plan vs Actual (계획 대비 실제):
    마이그레이션 중 마주한 설계상 구조적 제약과 이를 해결하기 위한 구현의 실제 간극 기록
  • ## Decision / Solution (의사결정):
    다양한 대안 라이브러리/아키텍처 중 해당 대안을 최종 낙점한 합리적인 엔지니어링 근거 기록
  • ## Caveats (주의점 및 제약):
    추후 유지보수 시 변경이 일어났을 때 사이드 이펙트를 유발할 수 있는 중대 제약 요소 박제
