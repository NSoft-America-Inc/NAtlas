# Slide 3: 문제의 본질 - 파편화와 소실의 카오스

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 단절되고 고립된 지식 조각들의 실태를 입체적으로 체감시키는 **3D 입체 혼란 캔버스 레이아웃 (3D Fragmented Chaos Canvas)**. 캔버스 화면의 구도를 비대칭으로 넓게 채워 긴장감과 몰입감을 선사합니다.
- **비주얼 및 컴포넌트 구성**:
  - **중앙**: 소용돌이치며 격렬하게 회전하는 붉은색 `KNOWLEDGE LOSS` 핵심 태풍 코어 SVG.
  - **부유 카드 컴포넌트**: `transform: rotate()` 회전각을 불규칙적으로 적용하여 사방에 둥둥 떠 있는 3개의 입체 퍼즐 카드 배치.
    - **Slack 대화방 카드 (좌측 상단, 적색)**: 비스듬히 떠 있어 단절감 부각.
    - **Jira 티켓 카드 (우측 상단, 청색)**: 한쪽으로 기울어진 모습으로 싱크 괴리 형상화.
    - **개발자 로컬 메모 카드 (하단 중앙, 황색)**: 고립된 위치로 인원 변동 시 유실 위험 시각화.

## 2. 실질적 본문 내용 (Exact Slide Content)

### 🌪️ 파편화와 만료 정책이 유발하는 전사 지식 증발 현상

엔지니어가 내린 고도의 아키텍처적 판단과 트레이드오프는 영구적인 코드베이스 문서로 안착하지 못하고 사방으로 쪼개져 소실됩니다. 지식이 한데 결속되지 못하고 파편화되는 구조적 통로는 크게 **3대 소실 Leak 채널**로 요약됩니다.

- **💬 Slack Chats [임시 대화방의 침묵]**: 
  - 리팩토링이나 마이그레이션 도중 주고받은 왜 이 포트나 라이브러리를 가두었는지에 대한 치열한 기술 논의. 사내 **3개월 히스토리 자동 만료 정책** 및 자연어 검색의 한계로 인해 시간이 흐르면 영구 유실되어 침묵합니다.
- **🎫 Jira Tickets [파일 실물과의 동기화 단절]**: 
  - 티켓 생성 시점에 대략 작성된 Context와 비즈니스 요구사항. 코드가 배포되고 빌드된 실제 물리 마일스톤과의 싱크 연동선이 완전히 단절되어, 나중에 코드를 볼 때 Jira 티켓 번호와 매핑해 인과관계를 추적하기가 불가능합니다.
- **📝 Local Memo & Scratch [개인 자산의 고립]**: 
  - 개발자 본인의 VS Code 스크래치 파일, 바탕화면 임시 메모장, 혹은 머릿속에만 암묵화되어 갇힌 개발 트레이드오프 결정 사항. 조직 내에서의 온보딩 전수나 인수인계, 혹은 퇴사 시 원천적으로 복원 불가능하게 증발합니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"우리가 겪는 문제의 본질은 지식 자체가 없어서가 아닙니다. 지식이 한데 묶이지 못하고 사방으로 쪼개져 흩어지는 '파편화와 소실'에 있습니다. 슬랙 대화방에서 치열하게 논의했던 왜 이 옵션을 켰는지에 대한 맥락은 3개월 뒤면 사라집니다. 지라 티켓에 적힌 내용은 실제 기재된 코드 실물과 싱크가 어긋납니다. 결국 가장 중요한 아키텍처적 의사결정은 개발자 개인의 머릿속이나 로컬 스크래치 파일에만 갇혀 있다가 퇴사나 전환과 동시에 완전히 유실되고 맙니다. 이 파편화의 소용돌이를 끝내고 영구 보존할 수 있는 기계 가독형 위키 체계를 도입해야만 합니다."*
