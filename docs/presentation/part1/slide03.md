# AI는 어제 대화를 기억하지 못한다 — 그래서 오늘도 처음부터

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 반복 루프를 시각화하는 **Repeat Cycle Layout**. 작업 → 종료 → 다음 날 시작 → 처음부터 설명 → 작업 → 반복. 원형 또는 연속 화살표 구조.
- **비주얼 및 컴포넌트 구성**:
  - **중앙 순환 다이어그램**: 4단계 루프.
    - ① 오늘: AI와 함께 기능 개발 완료
    - ② 내일: 새 채팅창 열기 → AI가 어제를 모름
    - ③ 다시: "우리 프로젝트는 이런 구조인데..." 설명 시작
    - ④ 또: 개발 완료 → 다음 날 반복
  - **루프 중앙 텍스트**: "이 반복, 매일 하고 있지 않으신가요?"
  - **우측 설명 패널**: 왜 이 구조가 팀 전체의 비용이 되는지.

## 2. 실질적 본문 내용 (Exact Slide Content)

### 새 채팅창 = 처음 만나는 사이 — 이 반복이 매일 쌓인다

AI 코딩 에이전트의 구조적 한계가 하나 있습니다. 새 채팅창을 열면 어제의 대화는 없습니다. 처음 만나는 사이입니다.

그래서 새 작업을 시작할 때마다 이렇게 됩니다:

*"우리 프로젝트는 React로 만든 웹앱인데요, 백엔드는 FastAPI고, 지난번에 이런 구조로 인증을 만들었었는데, 이번에는 이 부분을 수정해야 해서..."*

이 설명을 매번 해야 합니다. 개발자 혼자서도, 팀이 늘어도 이 문제는 해결되지 않습니다.

- 팀원이 바뀌어도: 새 사람은 처음부터 파악해야 합니다
- 작업이 이어져도: AI에게 매번 맥락을 다시 알려야 합니다
- 시간이 지나도: 쌓이는 코드만큼 설명해야 할 것도 늘어납니다

이 반복을 구조적으로 끊지 않으면, 팀이 클수록 이 비용도 함께 커집니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"AI의 가장 큰 한계 중 하나가 뭔지 아십니까? 어제 대화를 오늘 기억하지 못합니다. 새 채팅창을 열면 처음 만나는 사이입니다. 그래서 새 작업을 시작할 때마다 우리 프로젝트가 어떤 구조인지, 이전에 어떤 결정을 했는지, 이번에 뭘 해야 하는지를 다시 설명하게 됩니다. 혼자라도 피곤한데, 팀이 여러 명이면 이 설명이 몇 배로 늘어납니다. 이 반복을 끊는 방법이 있습니다."*
