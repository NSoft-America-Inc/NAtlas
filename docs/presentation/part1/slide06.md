# 코드를 몽땅 넘겨줬더니 — AI가 오히려 틀리는 이유

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 좌측에 "코드를 많이 줄수록 AI가 더 잘 할 것이라는 기대"와 우측에 "실제로 일어나는 일"을 대비하는 **Expectation vs Reality Layout**.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 (기대, 파란 계열)**: 코드 파일 아이콘 여러 개 → AI 아이콘 → "정확한 답변" 기대 배지. "맥락을 많이 줄수록 좋다"는 기대를 표현.
  - **우측 (현실, 로즈/주황)**: 코드 파일 아이콘 너무 많음 → AI 아이콘이 과부하 상태 → "엉뚱한 수정", "사이드 이펙트 발생" 배지. 정보가 너무 많을 때의 역효과.
  - **중앙 구분**: "코드 50개 파일 vs 핵심 문서 3개" 비교 배지.

## 2. 실질적 본문 내용 (Exact Slide Content)

### AI에게 코드를 많이 줄수록 좋을 것 같지만 — 실제로는 반대입니다

직관적으로 생각하면, AI에게 코드를 많이 줄수록 더 잘 이해하고 더 좋은 결과를 낼 것 같습니다. 그래서 프로젝트 파일을 몽땅 붙여넣거나, 관련 코드를 최대한 많이 포함하는 식으로 씁니다.

그런데 실제로는 이렇게 됩니다:

- **파일 수십 개를 넘기면**: AI가 어느 부분에 집중해야 하는지 판단하기 어렵습니다
- **코드가 많을수록**: 엉뚱한 부분을 수정하거나, 다른 기능이 깨지는 변경을 제안합니다
- **맥락이 희석됩니다**: 중요한 내용이 수만 줄의 코드 속에 묻힙니다

AI에게 필요한 것은 코드 전체가 아닙니다. **"왜 이렇게 만들었는지"를 핵심만 요약한 정보**입니다. 38개 파일 27만 자의 코드보다, 3종 지식 문서 1만 2천 자가 AI에게는 더 유용합니다.

이것이 다음에 보여드릴 해결책의 핵심 원리입니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"AI에게 코드를 많이 줄수록 잘 할 것 같은데, 실제로는 반대인 경우가 많습니다. 수십 개의 파일을 붙여넣으면 AI가 어디에 집중해야 하는지 모르게 됩니다. 핵심이 희석되는 거죠. 우리가 실제로 측정해봤습니다. 38개 파일 27만 자를 AI에게 그대로 주는 방식과, 그 코드에서 핵심만 뽑아 정리한 문서 3개 1만 2천 자를 주는 방식을 비교했습니다. 결과가 상당히 놀라웠습니다. 이건 다음 슬라이드에서 보여드리겠습니다."*
