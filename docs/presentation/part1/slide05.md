# Slide 5: 하이라이트 - 리버스 엔지니어링이 유일한 인수인계가 된 현실

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 복잡하고 중첩된 레거시 소스 코드를 해독하는 상황과 조직적 리스크 지표를 직관적으로 대비시키는 **디버거 코드뷰 & 리스크 대시보드 대비 레이아웃 (Debugger Code vs Risk Dashboard)**. 화면의 전체 마진을 조이고 디버그 줄 수와 리스크 매트릭스를 크게 배치해 화면이 꽉 찬 정보 밀도를 수립합니다.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 (Debugger Code View)**: 딥 다크 블랙 배경 위로 쏟아지는 난해한 비동기 스폰 자바스크립트 소스코드 숲. 소스코드 중 Cleanup 예외 처리가 유실된 채 `proc.on("exit")`이 무작정 기동되는 부위를 붉은색 돋보기 디버그 뷰포트로 감싸 돋보기 렌즈 글로우 효과 기재.
  - **하단 (Risk Alert Dashboard)**: 붉은색 경보 글로우 카드 내부로 수치 지표 정렬. **"의사결정 쏠림 98%"** (특정 1인 독점), **"코드 리분석 공수 4.5 Hrs"** (RAG 부재 시 매번 역공학 야근 폭주) 등의 수치를 붉은 네온 바 게이지와 연동 렌더링.

## 2. 실질적 본문 내용 (Exact Slide Content)

### 🚨 코드 역공학과 인력 단일 장애점(SPOF)에 노출된 비즈니스 위기

신규 임직원이 온보딩되거나 다른 파트의 엔지니어가 솔루션을 이관받아 유지보수하려고 할 때, 신뢰하고 기댈 수 있는 **"1차 문헌(Primary Source)"**이 부재합니다. 이로 인해 조직은 비즈니스 안전성을 위협하는 심각한 병목 상태에 지속 직면합니다.

- **🔍 소스코드 리버스 엔지니어링의 일상화 [야근의 원천]**: 
  - 과거 설계 의도가 적힌 문서가 전혀 없기 때문에, 엔지니어는 결국 수천 줄의 레거시 코드를 한 줄씩 뜯어 해독하며 역설계(Reverse Engineering)를 수행하는 소모적인 야근을 매번 강제당합니다.
- **🔥 인력 단일 장애점(SPOF) 리스크 폭발 [업무 쏠림 98%]**: 
  - 특정 피처의 설계 역사를 알고 있는 '오리지널 개발자 1인'에게 전사의 모든 기술 질문이 기형적으로 쏠려 심각한 업무 병목이 일어납니다. 
  - 만약 해당 1인이 자리를 비우거나 퇴사할 경우, 솔루션 변경 시 예기치 못한 크래시나 파손에 무방비로 노출되는 **"조직적 비즈니스 리스크"**가 지수함수적으로 증가합니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"우리가 겪는 가장 아픈 하이라이트는, '코드 리버스 엔지니어링'이 사내 솔루션의 유일한 인수인계 수단이 되어버린 현실입니다. 신규 팀원이 온보딩되거나 다른 파트에서 유지보수를 위임받았을 때, 의지할 1차 기술 문헌이 없으니 결국 좌측 화면처럼 수천 줄의 난해한 소스코드를 한 줄 한 줄 뜯어 해독하는 눈물의 리버스 엔지니어링 야근이 강제됩니다. 더 심각한 것은 특정 파일의 히스토리를 알고 있는 '유일한 한 사람'에게 모든 질문이 폭주하며, 그 1인이 휴가를 가거나 퇴사를 하면 시스템 전체가 파손 위기에 직면하는 인력 단일 장애점(SPOF)에 전 조직이 노출된다는 사실입니다. 우리는 이 비효율의 체계를 반드시 전사 컴파일러로 교정해야 합니다."*
