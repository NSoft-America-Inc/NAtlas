# AI가 코드를 짜줬다. 근데 왜 아무것도 안 남을까?

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 화면 중앙에 강렬한 질문 하나가 크게 놓이고, 그 아래 두 개의 대비 카드가 나란히 배치되는 **Question + Contrast Layout**. 좌측은 "빠른 개발"의 긍정, 우측은 "남은 것 없음"의 공백.
- **비주얼 및 컴포넌트 구성**:
  - **상단 헤드라인**: "AI가 코드를 짜줬다. 근데 왜 아무것도 안 남을까?" — 크고 굵게, 화면 상단 중앙 전체 폭.
  - **좌측 카드 (스카이블루 테두리)**: 로켓 아이콘 + "코드: 완성 ✓" + "속도: 10배 ✓". 빠른 개발의 긍정을 표현.
  - **우측 카드 (회색, 음영 처리)**: 빈 문서 아이콘 + "왜 이렇게 만들었는지: ?" + "다음 사람이 이해하려면: 처음부터 다시". 사라지는 맥락 표현.
  - **하단 작은 문구**: "이 질문에 답하는 것이 오늘 발표의 전부입니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### AI 시대의 역설 — 만드는 것은 빨라졌는데, 기억은 더 빨리 사라진다

AI 코딩 에이전트 덕분에 코드를 만드는 속도는 분명히 빨라졌습니다. 혼자서 하루에 처리하는 기능 수가 달라졌습니다.

그런데 시간이 지나고 그 코드를 다시 보면 낯설 때가 있습니다. 내가 만들었는데도.

왜 이렇게 만들었는지, 어떤 선택이 있었는지, 무엇을 고려했는지 — 코드 어디에도 없습니다.

- **남은 것**: 동작하는 코드
- **사라진 것**: 그 코드를 만든 이유와 판단의 흔적

이것이 반복되면, 팀 전체가 코드를 읽는 것만으로 상황을 파악해야 하는 구조가 됩니다.

## 3. 스피치 노트 (Aside Speaker Notes)

_"오늘 발표는 질문 하나로 시작하겠습니다. AI로 개발하고 나서 며칠 후에 그 코드를 다시 봤을 때 '이게 뭐지?' 싶었던 적 있으신가요? AI가 빠르게 만들어줬는데, 왜 이렇게 만들었는지는 어디에도 안 남아 있는 거죠. 오늘 발표는 바로 이 문제에 대한 이야기입니다. 어떻게 하면 빠른 개발과 남는 지식을 동시에 가져갈 수 있는지."_
