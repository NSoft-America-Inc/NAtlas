# 직접 측정해봤습니다 — 코드 전체 vs 핵심 문서 3개

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 측정 결과를 명확하게 보여주는 **Data Comparison Layout**. 좌측은 "코드 전체 방식"의 수치, 우측은 "핵심 문서 방식"의 수치. 개선 수치가 크고 강조되어 눈에 들어옴.
- **비주얼 및 컴포넌트 구성**:
  - **상단 맥락 설명**: "NAtlas 프로젝트 (38개 파일, 27만 자)를 대상으로 실측"
  - **비교 표**: 두 방식의 3가지 항목 수치 비교. 숫자가 크고 굵게.
  - **우측 개선 배지**: 각 항목별 개선율 — "95% 절감", "5배 빠름" 등 임팩트 있게 강조.
  - **하단 결론 문구**: "더 적은 정보로 더 빠르고 정확하게 — 핵심만 잘 정리된 문서의 힘."

## 2. 실질적 본문 내용 (Exact Slide Content)

### NAtlas 프로젝트 실측 — 코드 38개 파일을 그대로 vs 핵심 문서 3개

우리가 개발 중인 NAtlas 프로젝트(38개 파일, 약 27만 자)를 대상으로 두 가지 방식을 직접 비교 측정했습니다.

| 항목                       | 코드 전체를 AI에게 | 핵심 문서 3개를 AI에게 | 차이         |
| -------------------------- | ------------------ | ---------------------- | ------------ |
| **AI에게 전달되는 정보량** | 275,000자          | 12,000자               | **96% 감소** |
| **AI 응답 속도**           | 16.5초             | 3.2초                  | **5배 빠름** |
| **비용 (토큰)**            | 78,689 토큰        | 3,705 토큰             | **95% 절감** |

핵심 문서 3개란: 작업 지시서(order.md), 결과 기록(wiki.md), 진행 보고서(report.md). NStack이 만들어내는 문서들입니다.

더 적은 정보를 줬는데 AI가 더 빠르고 정확하게 작동합니다. 코드 전체보다 잘 정리된 핵심 문서가 AI에게 훨씬 유용한 정보이기 때문입니다.

## 3. 스피치 노트 (Aside Speaker Notes)

_"우리가 직접 측정했습니다. NAtlas 프로젝트 파일 38개, 약 27만 자를 AI에게 그대로 전달했을 때와, 그 프로젝트의 핵심을 정리한 문서 3개 1만 2천 자를 전달했을 때를 비교했습니다. 결과입니다. 비용은 95% 줄었고, 속도는 5배 빨라졌습니다. 더 적게 줬는데 더 잘 됩니다. 왜냐하면 AI에게 필요한 건 코드 전체가 아니라, 왜 이렇게 만들었는지를 잘 정리한 핵심 정보이기 때문입니다. NStack은 이 핵심 문서 3종을 개발 과정에서 자동으로 만들어주는 방법론입니다."_
