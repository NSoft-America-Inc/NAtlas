# 코드가 쌓일수록 이해하는 데 걸리는 시간도 함께 쌓인다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 시간에 따라 코드 양과 이해 비용이 함께 증가하는 구조를 보여주는 **Growth Curve Layout**. 코드 양은 선형으로 증가하지만 이해 비용은 더 가파르게 증가하는 그래프.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 그래프 SVG**: X축(시간/프로젝트 규모), Y축(비용). 코드 양(파란 선, 완만한 상승)과 이해 비용(붉은 선, 더 가파른 상승)이 점점 격차를 벌리는 모습.
  - **우측 설명 패널**: 코드 100줄일 때 vs 10,000줄일 때 새로운 기능 추가에 걸리는 평균 이해 시간 비교.
  - **하단 강조**: "AI가 만드는 속도는 빠르지만, 쌓이는 이해 비용은 막아주지 않습니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### 왜 프로젝트 초기보다 나중에 새 기능 추가가 더 오래 걸리는가

프로젝트 초반에는 새 기능을 추가하는 게 빠릅니다. 코드가 적고, 전체 구조를 머릿속에 담고 있기 때문입니다.

그런데 6개월이 지나면? 1년이 지나면?

- **코드가 100줄일 때**: 새 기능 추가 전 파악 시간 — 수 분
- **코드가 10,000줄이 되면**: 새 기능이 어디에 영향을 주는지 파악 시간 — 수 시간에서 수일
- **코드가 AI로 빠르게 만들어졌다면**: 왜 이런 구조인지 설명이 없어 파악 시간이 더 길어짐

이것은 개인의 능력 문제가 아닙니다. **기록이 없는 코드베이스가 커질수록 이해 비용이 비선형으로 늘어나는** 구조적 문제입니다.

AI가 코드를 빠르게 만들어 줄수록, 이 문제는 더 빠르게 쌓입니다. 만드는 속도는 빨라졌지만 이해 비용을 낮춰주지는 않기 때문입니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"프로젝트 초반에는 새 기능을 빠르게 추가할 수 있습니다. 전체 구조가 머릿속에 있으니까요. 그런데 6개월, 1년이 지나면 새 기능 하나를 추가하기 전에 '이걸 건드리면 어디가 영향받지?'를 파악하는 데만 하루가 걸리는 경우가 생깁니다. 코드가 쌓일수록 이해 비용도 함께 쌓이는 겁니다. AI로 코드를 빠르게 많이 만들면 이 문제가 더 빠르게 쌓입니다. 만드는 속도는 AI가 높여줬는데, 이해하는 비용을 낮춰주는 건 아무것도 없는 거죠."*
