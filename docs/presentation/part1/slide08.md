# Slide 8: 코드베이스 팽창의 부담 - 역공학(Reverse Engineering)의 치명적 비효율

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 코드 라인수의 증가에 따른 토큰 비용의 폭발적 성장을 시각화하여 충격을 주는 **지수함수적 토큰 비용 폭발 차트 (Exponential Token Blast Chart)**.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 비주얼**: 가로축(코드 규모), 세로축(소모 토큰량)을 기준으로 곡선이 하늘을 뚫고 지수 함수적으로 치솟는 지환형 차트 SVG 탑재.
  - 임계점 근방에 번쩍이는 붉은색 네온 번개 경보 마크(`FEE EXPLOSION`)와 무겁게 누적되는 데이터 바(Bar) 패킷 렌더링.

## 2. 실질적 본문 내용 (Exact Slide Content)

### 📈 프로젝트 규모 팽창에 따른 에이전트 인프라 비용 폭발

신규 기능이 지속적으로 이식되고 마이그레이션이 반복되면서 프로젝트의 코드 규모는 5,000줄에서 50,000줄 이상으로 무섭게 팽창합니다. 이 상황에서 문서가 없어 과거 히스토리를 분석하기 위해 전체 소스코드를 에이전트에 매번 로드하는 **"Naive 전체 역공학 방식"**은 파괴적인 비효율을 자아냅니다.

- **💸 토큰 과금의 기하급수 폭증 [Cost Explosion]**: 
  - 코드가 비대해질수록, 에이전트가 단 1줄의 신규 로직을 고치기 위해 백그라운드에서 전체 구조를 학습하느라 삼켜내는 입력 토큰(Input Tokens) 요금이 기하급수적으로 치솟습니다.
- **⏳ 에이전트 인지 속도 마비 [Cognitive Delay]**: 
  - LLM 에이전트가 수십 개의 파일을 한꺼번에 분석하고 이해하는 데 막대한 하드웨어 병목과 시간 지연이 발생합니다. 
  - 쿼리 한 번당 응답 지연이 30초 이상 증가하며 작업 리듬이 완전히 파손됩니다.
- **📉 정교성 및 코드 안전성 저하 [Diluted Attention]**: 
  - 에이전트의 주의력(Attention)이 너무 넓은 코드 숲에 희석되어, 정작 해결해야 할 완료 기준(Criteria)을 정확하게 지키지 못하고 엉뚱한 부위에 버그를 양산하는 비극적 한계에 부딪힙니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"대다수 개발 리더들이 간과하는 심각한 사실이 있습니다. 프로젝트 초기에 코드가 5,000줄 수준일 때는 에이전트가 소스코드를 통째로 읽어도 요금이나 속도 면에서 티가 나지 않습니다. 그러나 기능이 추가되어 프로젝트가 5만 줄 이상으로 팽창하면 상황은 완전히 파멸적입니다. 단 10줄을 고치기 위해 과거 히스토리를 파악하려고 전체 소스를 LLM에 올릴 때마다 수만 개의 토큰이 증발하며 비용이 수십 배로 폭증하죠. 정작 에이전트는 무거운 코드를 분석하느라 정력을 다 소진하여, 엉뚱한 부위에 버그를 뿜는 최악의 한계에 마주칩니다. 우리는 이 지수함수적인 토큰 폭발을 기계적으로 격리해야 합니다."*
