# 해결책은 단순합니다 — 작업할 때마다 '이유'를 함께 저장한다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 단순한 3단계 흐름을 보여주는 **Three-Step Flow Layout**. 좌측에서 우측으로 흐르는 화살표 구조. "이렇게 작동합니다"가 직관적으로 보임.
- **비주얼 및 컴포넌트 구성**:
  - **3개의 문서 카드 (가로 배치)**:
    - **카드 1 (파랑)**: 📋 작업 지시서 `order.md` — "오늘 무엇을, 왜, 어디까지"
    - **카드 2 (퍼플)**: 🧠 지식 보존서 `wiki.md` — "왜 이렇게 만들었는가"
    - **카드 3 (에메랄드)**: 📊 진행 보고서 `report.md` — "무엇을 했고 무엇이 남았는가"
  - **하단 연결 문구**: "이 3종 문서가 쌓이면 — AI는 매번 새로 시작하지 않습니다"
  - **우측 배지**: "38개 파일 → 문서 3개 / 275,000자 → 12,000자"

## 2. 실질적 본문 내용 (Exact Slide Content)

### 코드는 "무엇을 만들었는가"를 보여준다. 문서는 "왜 이렇게 만들었는가"를 보여준다.

해결책은 복잡하지 않습니다. 작업할 때마다 코드와 함께 이유도 저장하면 됩니다.

NStack은 3종 문서를 개발 과정에서 자동으로 만들어냅니다:

| 문서                        | 역할    | 담는 내용                                      |
| --------------------------- | ------- | ---------------------------------------------- |
| **작업 지시서 (order.md)**  | 작업 전 | 오늘 무엇을, 왜, 어디까지 할 것인가            |
| **지식 보존서 (wiki.md)**   | 작업 후 | 왜 이 구조를 선택했는가. 어떤 고민이 있었는가  |
| **진행 보고서 (report.md)** | 작업 중 | 무엇을 했고, 무엇이 남았고, 무엇을 알게 됐는가 |

이 3종 문서가 쌓이면:

- **AI는 매번 새로 시작하지 않아도 됩니다** — 다음 대화에서 문서를 주면 AI가 맥락을 바로 이어받습니다
- **사람도 처음부터 읽지 않아도 됩니다** — 인수인계, 복귀, 온보딩 모두 문서 3개로 해결됩니다
- **38개 파일 27만 자를 3개 문서 1만 2천 자로 압축합니다** — 정보는 95% 줄었지만 이해는 더 빠릅니다

## 3. 스피치 노트 (Aside Speaker Notes)

_"해결책은 단순합니다. 작업할 때마다 코드만 만들지 말고, 왜 이렇게 만들었는지도 함께 저장하면 됩니다. NStack은 이걸 3종 문서로 만들어냅니다. 작업 지시서, 지식 보존서, 진행 보고서. 이 세 개가 쌓이면 AI는 다음 대화에서 맥락을 바로 이어받을 수 있고, 사람도 인수인계 때 처음부터 코드를 읽을 필요가 없어집니다. 38개 파일 27만 자의 코드보다, 이 문서 3개 1만 2천 자가 훨씬 더 유용한 정보입니다. 코드는 무엇을 만들었는지 보여주지만, 문서는 왜 이렇게 만들었는지를 보여줍니다."_
