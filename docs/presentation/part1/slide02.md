# AI 덕분에 빨라졌다 — 그런데 왜 더 피곤한 것 같을까?

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 저울(天秤) 형태의 비교 레이아웃. 좌측은 "AI 도입 후 좋아진 것", 우측은 "AI 도입 후 생긴 새로운 피로". 저울이 균형을 못 잡는 모습으로 역설을 표현.
- **비주얼 및 컴포넌트 구성**:
  - **중앙 저울 SVG**: 왼쪽(긍정)이 무겁지만 오른쪽(피로)도 만만치 않게 올라가는 불균형 저울.
  - **좌측 (초록 체크)**: "코드 생성 속도 ↑" / "기능 구현 수 ↑" / "혼자 할 수 있는 범위 ↑"
  - **우측 (주황 느낌표)**: "AI에게 매번 처음부터 설명" / "맥락을 다시 찾는 시간" / "동료에게 설명하기 어려운 코드"
  - **하단 한 줄**: "빠른 것과 남는 것은 다른 문제입니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### AI 도입 후 실제로 생긴 일 — 좋아진 것과 새로 생긴 피로

AI 코딩 에이전트를 도입하면 분명히 좋아지는 것들이 있습니다. 코드를 만드는 속도, 한 사람이 커버할 수 있는 범위. 이건 사실입니다.

그런데 동시에 새로운 종류의 피로가 생겼습니다.

- **좋아진 것**:
  - 기능 구현 속도가 빨라졌다
  - 혼자서도 더 넓은 범위를 처리할 수 있다
  - 반복 작업이 줄었다

- **새로 생긴 것**:
  - AI에게 새 작업을 시킬 때마다 프로젝트 배경을 처음부터 설명해야 한다
  - 동료가 "이 코드 왜 이렇게 됐어?"라고 물어볼 때 설명하기 어렵다
  - 한 달 전에 AI와 함께 만든 코드를 다시 볼 때 낯설다

빠르게 만드는 것과, 만든 것이 제대로 남는 것은 다른 문제입니다.

## 3. 스피치 노트 (Aside Speaker Notes)

_"AI 도입하고 나서 개발이 더 빨라진 건 맞습니다. 부정하는 게 아닙니다. 그런데 이상하게 더 피곤해진 것 같다는 분들이 있습니다. 속도는 빨라졌는데, AI에게 매번 처음부터 설명해야 하고, 만든 결과물이 어떤 이유로 만들어졌는지 남지 않습니다. 빠른 것과 남는 것은 다른 문제입니다. 오늘 이 발표는 이 두 가지를 동시에 잡는 방법에 대한 이야기입니다."_
