# Slide 24: 듀얼 트랙 지식 흐름도 2 - AI 에이전트 관점의 E2E Flow

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: AI 에이전트가 최소한의 토큰 리소스를 소모하며 초정밀 코딩을 구사하고 최종 지식을 자산으로 반환하는 **에이전트 RAG 순환 레이아웃 (Agent RAG Cycle Layout)**.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 비주얼**: 퍼플 네온 및 에메랄드 네온의 입체 무한 루프 순환체. 중앙에서 빛나는 AI 에이전트(LLM) 코어로 **[SwarmVault 시맨틱 검색] ➔ [Citations 단기기억 증강 (95% 토큰 세이빙)] ➔ [order.md 하네스 정밀 코딩] ➔ [wiki.md 이중대괄호 지식 환원]**의 4단계 순환 피드백 고리가 펄스 레이저 모션 화살표로 휘돌아 나가는 역동적 SVG 도식 탑재.
  - AI 최적화 지표인 **🤖 LLM TOKEN MINIMIZER & CONTEXT BOUND ACTIVE** 라벨 적용.

## 2. 실질적 본문 내용 (Exact Slide Content)

### 🤖 전체 소스코드를 역공학하지 않고, 시맨틱 링크만으로 3초 만에 설계 의도를 읽어내는 기계

인간 개발자의 관점을 살펴보았으니, 이제 기계인 **AI 코딩 에이전트(LLM)의 관점**에서 이 파이프라인이 얼마나 환상적으로 리소스를 아끼며 고도의 정밀성을 발휘하는지 살펴볼 차례입니다. 전체 코드를 탐색하기 위해 매번 수만 줄의 소스 코드를 LLM에 통째로 우겨넣어 에이전트의 단기 기억을 파괴하고 수십 달러의 토큰 요금을 탕진하던 치명적인 오버헤드가 기계적 RAG 순환계를 통해 완전히 근절됩니다.

- **🔍 1단계: SwarmVault Query [시맨틱 지식 인출]**:
  - 에이전트는 코드베이스를 읽기 전, SwarmVault API를 기동해 로컬 SQLite 벡터 DB에서 관련 개발 히스토리를 초고속 시맨틱 검색합니다.
- **⚡ 2단계: Context Augmentation [95.29%의 토큰 다이어트]**:
  - 에이전트는 날것의 소스 코드 38개 파일(78,689 토큰) 대신, 압축 복기된 3종 지식 문서(3,705 토큰)만을 컨텍스트에 쏙 Citations 주입받아 단기기억을 완벽하고 가볍게 증강합니다.
- **🏗️ 3단계: Harness Coding [하네스 가두리 코딩]**:
  - 에이전트는 주입받은 단기 기억과 `order.md`가 규정해 둔 엄격한 요구 사양 가두리 안에서 한 치의 오차와 이탈도 없는 정밀 코딩을 집행합니다.
- **🔄 4단계: Wiki Return [이중 대괄호 지식 환원]**:
  - 작업을 마친 에이전트는 린팅 자가 검사를 끝내고, 다른 아티팩트 노드들과 연결될 수 있도록 **`[[이중 대괄호]]`** 시맨틱 링크 스펙을 장착한 `wiki.md`를 작성하여 SwarmVault 저장소로 환원 축적합니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"인간 개발자의 관점에 이어, 이번 장은 기계인 'AI 에이전트' 시점의 흐름입니다. 보통 에이전트와 코딩을 해 보면 수만 줄의 코드를 통째로 넘겨받는 비효율 때문에 똑똑하던 AI도 금방 단기 기억 상실증에 걸리고 수십 달러의 요금 폭탄을 안깁니다. 이 비효율을 완벽히 해결하는 것이 바로 이 4단계 'Agent RAG Cycle' 순환계입니다. 에이전트는 분석을 시작하기 직전, SwarmVault 엔진에 시맨틱 쿼리를 날려 과거의 3종 마크다운 조각들만 신속하게 찾아냅니다. 7만 8천 개의 소스코드 토큰 대신 단 3,700개의 핵심 지식 토큰만 단기 기억에 쏙 주입받아 증강하는 것이죠. 비용이 무려 95.29%나 실측 절감됩니다! 가볍고 똑똑해진 상태에서 `order.md`가 쳐 놓은 안전 하네스 펜스 안에서 정밀 코딩을 하고, 마지막으로 `[[이중 대괄호]]` 링크를 적용한 `wiki.md` 지식을 다시 SwarmVault로 도로 환원하여 저장합니다. 기계가 스스로 지식을 인출하고 증강하며 다시 환원하는 똑똑한 자급자족 순환계를 완성한 것입니다."*
