# AI 시점에서 본 NStack 흐름 — 왜 AI가 더 잘 작동하는가

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: AI가 어떻게 맥락을 받아서 작업하는지 보여주는 **AI Perspective Flow**. 개발자 흐름과 대비해서 AI 역할에 집중.
- **비주얼 및 컴포넌트 구성**:
  - **좌측 (맥락 전달)**: "AI가 받는 것" — order.md (오늘 할 일), wiki.md (과거 지식), report.md (진행 상황). 3개 문서 아이콘 → AI 아이콘.
  - **중앙 (AI 작업)**: AI가 이 맥락을 바탕으로 코드를 작성하는 모습. "코드 전체를 읽지 않아도 됩니다"
  - **우측 (결과)**: 코드 + 문서가 함께 완성됨. "다음 작업을 위한 맥락도 업데이트됩니다"
  - **하단 대비**: "맥락 없이 시작" (16.5초, 틀린 결과) vs "문서 3개로 시작" (3.2초, 정확한 결과)

## 2. 실질적 본문 내용 (Exact Slide Content)

### AI가 잘 작동하려면 — 코드 전체가 아니라 핵심 맥락이 필요합니다

AI 에이전트가 작업을 시작할 때 두 가지 방식이 있습니다:

**방식 A: 코드 전체를 AI에게 주는 방법**
- 38개 파일, 27만 자를 전달합니다
- AI가 어디에 집중해야 할지 판단하기 어렵습니다
- 응답 속도: 16.5초 / 토큰: 78,689개

**방식 B: 핵심 문서 3개를 AI에게 주는 방법 (NStack)**
- order.md (오늘 할 일) + wiki.md (과거 맥락) + report.md (현재 상황)
- AI가 맥락을 바로 이해하고 집중해서 작업합니다
- 응답 속도: 3.2초 / 토큰: 3,705개 (95% 절감)

**NStack이 가능하게 만드는 것:**
- 매 작업마다 이 3개 문서가 자동으로 업데이트됩니다
- 다음 AI 대화에서는 처음부터 설명하지 않아도 됩니다
- AI가 갈수록 더 잘 작동합니다 — 맥락이 쌓이기 때문입니다

## 3. 스피치 노트 (Aside Speaker Notes)

*"AI 시점에서 NStack이 어떻게 작동하는지 보겠습니다. AI에게 코드 38개 파일 전체를 주는 것과, 핵심을 정리한 문서 3개를 주는 것을 비교해봤습니다. 결과는 앞서 보신 것처럼 응답 속도 5배 차이, 비용 95% 차이입니다. NStack은 매 작업마다 이 문서 3개를 자동으로 업데이트합니다. 다음 번에 AI에게 이 문서를 주면, AI는 맥락을 바로 이어받습니다. 처음부터 설명하지 않아도 됩니다. 지식이 쌓일수록 AI가 갈수록 더 잘 작동하는 구조입니다."*
