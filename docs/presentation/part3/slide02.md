# 코드가 배포되기 전 — 마지막으로 한 번 더 자동 점검합니다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 개발자 → CI 점검 → 배포 흐름을 보여주는 **Pipeline Gate Layout**. 좌에서 우로 흐르는 파이프라인, 중간에 자동 점검 게이트.
- **비주얼 및 컴포넌트 구성**:
  - **파이프라인 흐름 (좌→우)**:
    - `개발자가 코드 올림` → `자동 점검 실행` → 분기: `✅ 통과 → 배포됨` / `❌ 문제 발견 → 배포 차단`
  - **자동 점검 게이트 (중앙, 에메랄드 방패)**:
    - "로컬에서 통과 + CI에서 통과 → 두 번 확인"
  - **하단 강조**: "개인 실수가 팀 전체에 영향을 주기 전에 — 시스템이 먼저 잡아냅니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### 로컬에서 확인했는데 팀 저장소에 올리면 또 한 번 확인합니다

NStack 자동 검사는 두 단계에서 작동합니다:

**1단계: 개발자 PC에서 (로컬)**

- 커밋할 때마다 자동 실행됩니다
- 문서에 문제가 있으면 → 커밋 자체가 차단됩니다
- 로컬에서 먼저 걸러집니다

**2단계: 팀 저장소에 올릴 때 (CI)**

- Pull Request를 올리면 자동으로 다시 검사합니다
- 로컬 환경이 달라서 통과된 것도 → 한 번 더 확인합니다
- 모든 팀원의 코드가 동일한 기준으로 검사됩니다

**왜 두 번 검사하는가**:

- 실수는 혼자 일할 때 나옵니다
- 팀 저장소에 올라가기 전에 반드시 한 번 더 확인이 필요합니다
- "내 PC에서는 됐는데" 상황을 방지합니다

결과: 팀장이 매 PR마다 문서를 수동으로 검수하지 않아도 됩니다. 시스템이 기준을 지킵니다.

## 3. 스피치 노트 (Aside Speaker Notes)

_"NStack 자동 검사는 두 단계에서 작동합니다. 개발자 PC에서 커밋할 때 한 번, 팀 저장소에 올릴 때 CI에서 한 번 더. 이중으로 확인하는 이유는 단순합니다. 실수는 혼자 있을 때 납니다. 팀 전체에 영향을 주기 전에 시스템이 먼저 잡아내는 것입니다. 팀장이 매 PR마다 '문서 제대로 썼어요?'를 확인하지 않아도 됩니다. 구조가 알아서 합니다."_
