# 개발자 시점에서 본 NStack 전체 흐름

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 개발자 관점의 전체 흐름을 왼쪽에서 오른쪽으로 보여주는 **Developer Journey Map**. 시연 전 로드맵 역할.
- **비주얼 및 컴포넌트 구성**:
  - **상단 헤드라인**: "오늘 시연에서 이 흐름 전체를 보여드립니다"
  - **흐름 다이어그램 (5단계, 좌→우)**:
    - `① 작업 계획` (order.md 작성, 파랑) → `② AI가 구현` (코드 생성, 퍼플) → `③ 자동 검사` (문서 검증, 에메랄드) → `④ 지식 기록` (wiki.md, 에메랄드) → `⑤ 저장소에 배포` (커밋 + CI, 앰버)
  - **각 단계 아래 작은 텍스트**: 개발자가 하는 일 vs AI가 하는 일 구분
  - **하단**: "이 흐름이 반복될수록 — 팀의 지식이 자동으로 쌓입니다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### 시연 전 로드맵 — 오늘 이 흐름 전체를 직접 보여드립니다

NStack을 쓰는 개발자의 한 작업 사이클 전체입니다:

**① 작업 계획 (개발자, 5분)**

- order.md를 작성합니다 — 왜, 무엇을, 어디까지

**② AI가 구현 (AI)**

- order.md를 보고 코드를 만듭니다
- 개발자는 방향을 확인합니다

**③ 자동 검사 (시스템)**

- 문서가 제대로 됐는지 자동으로 확인합니다
- 문제가 있으면 저장을 차단합니다

**④ 지식 기록 (AI + 개발자)**

- wiki.md에 왜 이렇게 만들었는지 기록합니다
- AI가 초안을 씁니다

**⑤ 배포 (자동)**

- 저장소에 올라가면 CI에서 한 번 더 확인합니다
- 통과하면 팀 저장소에 저장됩니다

이 사이클이 반복될 때마다 팀의 지식이 한 층씩 쌓입니다. 오늘 시연에서 이 전체 흐름을 보여드립니다.

## 3. 스피치 노트 (Aside Speaker Notes)

_"시연을 시작하기 전에 오늘 보여드릴 흐름을 한 번 정리하겠습니다. 작업 계획 → AI 구현 → 자동 검사 → 지식 기록 → 배포. 이 5단계가 NStack을 쓰는 개발자의 한 작업 사이클입니다. 개발자가 직접 하는 것은 시작 5분과 마지막 확인뿐입니다. 나머지는 AI와 시스템이 합니다. 이 흐름이 오늘 시연에서 실제로 어떻게 작동하는지 보여드리겠습니다."_
