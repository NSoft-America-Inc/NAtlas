# 시연 1 완료 — 코드도 됐고, 이유도 남았습니다

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 완료 결과를 두 열로 보여주는 **Completion Split Layout**. 좌측에 코드 결과, 우측에 문서 결과.
- **비주얼 및 컴포넌트 구성**:
  - **상단 큰 배지**: "✅ 시연 1 완료" (에메랄드)
  - **좌측 (코드 결과)**:
    - 완성된 Todo 앱 화면 스크린샷
    - `index.html`, `app.js`, `style.css` 파일 아이콘
    - "작동하는 앱이 만들어졌습니다"
  - **우측 (문서 결과)**:
    - `order.md` ✅, `wiki.md` ✅, `report.md` ✅ 아이콘
    - "왜 만들었는지 기록이 남았습니다"
    - "다음 AI 대화에서 이어받을 수 있습니다"
  - **하단 전환 문구**: "이제 이 지식을 이어받아 — React로 마이그레이션합니다"

## 2. 실질적 본문 내용 (Exact Slide Content)

### 시연 1에서 만들어진 것

**코드:**
- Todo 대시보드 앱 (Vanilla JS)
- 할 일 추가, 완료, 삭제 기능
- 로컬 저장 기능
- 작동하는 앱이 완성됐습니다

**문서 (자동 생성됨):**
- `order.md` — 왜 이 앱을 만들었는지 (이미 작성했음)
- `wiki.md` — 어떤 구조로 만들었는지, 어떤 결정을 했는지 (AI가 자동 생성)
- `report.md` — 무엇을 했고 무엇이 완성됐는지 (AI가 자동 생성)

**이게 왜 중요한가:**
- 지금 만든 코드의 이유가 문서로 남았습니다
- 6개월 뒤에 이 코드를 보면 — 문서를 보면 됩니다
- 시연 2에서 AI가 이 문서를 보고 마이그레이션을 시작합니다

마이그레이션에서 가장 중요한 것: **AI가 처음부터 설명 안 해도 됩니다.** 방금 쌓인 문서가 맥락을 전달합니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"시연 1이 완료됐습니다. 만들어진 것은 두 가지입니다. 하나는 작동하는 앱 — Todo 대시보드입니다. 다른 하나는 문서입니다. order.md, wiki.md, report.md 세 개가 자동으로 만들어졌습니다. 이 문서들이 왜 이 앱을 이런 구조로 만들었는지를 담고 있습니다. 이제 시연 2로 넘어가겠습니다. 이 앱을 React로 마이그레이션합니다. 중요한 것은 AI가 처음부터 설명 안 해도 된다는 점입니다. 방금 만들어진 문서가 맥락을 그대로 전달합니다."*
