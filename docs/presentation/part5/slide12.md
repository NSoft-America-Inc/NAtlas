# Slide 47-A: 프로젝트 관리자 시점 — NAtlas로 팀 전체 현황 파악

## 1. 화면 정의 및 레이아웃 (Layout Specification)

- **레이아웃 구조**: 프로젝트 관리자가 NAtlas를 열고 팀 현황을 파악하는 시나리오를 스토리보드 형식으로 보여주는 **PM Scenario Storyboard Layout**. 3개의 장면 카드가 가로로 나열되고 각 카드에는 "질문 → NAtlas 화면 → 답변" 구조가 담깁니다.
- **비주얼 및 컴포넌트 구성**:
  - **장면 1**: "이 기능 누가 만들었지?" → Documents 탭 검색 화면 → 담당자와 작업지시서 즉시 확인.
  - **장면 2**: "이 프로젝트들이 어떻게 연결돼 있지?" → 3D 지식 지도 → 노드 연결 관계 시각화.
  - **장면 3**: "이번 주 어떤 작업이 완료됐지?" → 문서 목록 필터 → 완료된 wiki.md 목록.
  - 상단 배너: "하루에 한 번 NAtlas를 열면, 팀 전체가 무엇을 했는지 10초 만에 파악된다."

## 2. 실질적 본문 내용 (Exact Slide Content)

### 📊 프로젝트 관리자는 NAtlas를 어떻게 쓰는가 — 회의 없이 현황 파악

프로젝트 관리자가 팀 현황을 파악하기 위해 매일 슬랙을 뒤지고, 팀원에게 "지금 어디까지 됐어요?"라고 물어보는 시간을 줄일 수 있습니다. NStack 워크플로우가 쌓인 저장소를 NAtlas로 열면, 팀이 무엇을 했는지가 **이미 기록**되어 있습니다.

- **🔍 시나리오 1 — "이 기능, 왜 이렇게 만들어진 거야?"**:
  - Documents 탭을 열고 해당 이슈 번호나 기능명을 검색합니다.
  - 담당자가 작성한 order.md와 wiki.md가 즉시 표시됩니다.
  - 설계 이유, 선택한 방법, 고려했던 대안까지 한 번에 파악됩니다.
- **🗺️ 시나리오 2 — "이 모듈들이 어떻게 연결되어 있지?"**:
  - 3D 지식 지도를 열면 프로젝트 간 연결 관계가 시각적으로 펼쳐집니다.
  - 클릭 한 번으로 관련 문서로 바로 이동합니다.
- **📋 시나리오 3 — "이번 주 어떤 작업이 완료됐지?"**:
  - 날짜 필터로 이번 주 완료된 문서 목록을 즉시 확인합니다.
  - 별도 보고 없이 진행 현황을 파악할 수 있습니다.

## 3. 스피치 노트 (Aside Speaker Notes)

*"NAtlas가 개발자만을 위한 도구라고 생각하시면 안 됩니다. 프로젝트 관리자에게도 강력한 도구입니다. 매일 아침 팀원에게 '어디까지 됐어요?'라고 물어보는 대신, NAtlas를 열면 됩니다. NStack 워크플로우가 쌓인 저장소라면, 팀원들이 어떤 작업을 했는지, 왜 그런 결정을 내렸는지, 어떤 문제가 있었는지가 이미 기록되어 있습니다. 특히 3D 지식 지도는 프로젝트 전체의 연결 구조를 한눈에 보여주기 때문에, 여러 모듈 간의 의존 관계나 영향 범위를 시각적으로 파악하는 데 매우 유용합니다. 보고서를 따로 만들 필요 없이, NAtlas가 그 역할을 대신해 줍니다."*
